# План тестирования DEEPoS на реальной консоли (R36S-V20)

Документ для этапа 2: проверка собранного образа на клоне `R36S-V20 2025-05-18`.
Пока консоль не подключена, все проверки ниже — ручные по чек-листу; автоматические
тесты (host) уже покрывают раскладку образа, протоколы модулей, хранилище сейвов,
сборку DTS и конфигов.

## 0. Что должно быть готово до прошивки

Для V20 с отсутствующей картинкой на исходной сборке используется
[диагностический профиль ядра Arch‑R](V20-BOOT-DIAGNOSIS.md). Его сборка
и проверка приведены отдельно.

| Артефакт | Проверка |
|---|---|
| Образ карты | SHA‑256 совпадает с `docs/RELEASE.md` |
| Загрузчик Arch-R clone | Область 32 КиБ–16 МиБ побайтово совпадает с проверенным донором |
| BOOT | `boot.scr` вызывает extlinux, SHA‑256 скрипта и файлов BOOT совпадают с манифестом |
| Ядро, DTB и rootfs | Размеры и SHA‑256 совпадают с `docs/RELEASE.md` |

Для V20 с донором указать путь к проверенному образу Arch‑R в `LOADER_DONOR`.
Сборка сама упакует `boot.scr` и вставит загрузчик.

```sh
make image-full LOADER_DONOR=/path/to/ArchR-clone.img.gz
make preflight LOADER_DONOR=/path/to/ArchR-clone.img.gz
make release LOADER_DONOR=/path/to/ArchR-clone.img.gz
```

Проверка `preflight` должна вернуть `GO`. Она проверяет файлы BOOT, конфиг
extlinux, rootfs, обе копии GPT и соответствие выбранному донору.
Для первого теста используется образ на 4 ГиБ. При записи на большую карту
резервная GPT переносится в физический конец, объём exFAT задаётся при сборке.
Для нового готового образа на всю пустую карту задать `SIZE_MIB` по её размеру.

## 0.5. Смоук-тест после первого буста

Первое, что стоит запустить на устройстве — встроенный отчёт об окружении:

```sh
/usr/bin/launcher --selftest
```

Ожидаемые строки (ключ=значение, парсится глазами и скриптом):

| Строка | Что значит | Норма на R36S-V20 |
|---|---|---|
| `version=0.4` | версия лаунчера | совпадает с `docs/metrics.md` |
| `roms=… systems=N games=M` | найдены системы и игры | `systems>0` при непустом ROMS |
| `data=… continue=N` | прочитанный `continue.tsv` | `N` равно числу строк файла |
| `emulators=… emulators_present=1` | найден `emulators.toml` | 1 |
| `modd=… modules=N` | связь с супервизором через `/run/modd.sock` | `N` = число модулей в `/data/modules` |
| `fb=… fb_present=1` | фреймбуфер | 1 (иначе смотреть `CONFIG_DRM_FBDEV_EMULATION`) |
| `input_events=N` | устройства ввода | ≥1 (`gpio-keys` и/или `adc-joystick`) |
| `status=ok` | отчёт дошёл до конца | ok |

Если `input_events=0` — кнопки не заведены: проверить `dmesg | grep -i key` и DTS
(`gpio-keys`/`adc-joystick`). Если `fb_present=0` — нет `/dev/fb0` (fbdev emulation).

## 1. Бэкап текущего состояния

1. Снять полный образ стоковой/рабочей карты (Arch-R) через Win32DiskImager Read
   или `dd` на Linux; сохранить `*.img.gz` + `sha256`.
2. Скопировать `BOOT` и `ROM-раздел` папками (быстрее восстановить отдельные файлы).
3. Записать в журнал версию Arch-R (`archr-update version`), ядра (`uname -r`) и
   модель панели из `/proc/device-tree/model`.

## 2. Прошивка

Определить номер тестовой microSD через `Get-Disk` и сверить модель и ёмкость.
Из PowerShell с правами администратора подставить номер карты и SHA-256 образа.

```powershell
.\flash-deepos.ps1 -Image build/deepos-r36s-v20.img -Sha256 $sha256
```

Скрипт сверяет хеш до очистки карты. `dpflash` записывает основную GPT после
проверки полезной нагрузки, сбрасывает кэш записи и считывает таблицу обратно.
На карте большего размера резервная GPT записывается в конец носителя. Размеры
разделов сохраняются. После успешной проверки и сообщения `DONE` извлечь карту и вставить в консоль.

## 3. Первый буст — что должно произойти

1. U-Boot SPL → `u-boot.itb` → `boot.scr` → `extlinux.conf` с `LABEL DEEPoS`.
2. Ядро монтирует `PARTLABEL=DEEPOS_A` (squashfs, ro). `rcS` определяет карту по
   major:minor корневого монтирования, запускает `mdev` и монтирует с той же карты
   BOOT (p1) в `/flash`, DATA (p4) в `/data`, ROMS (p5) в `/storage`.
   В консоли появляется `DEEPoS: storage=ok data=ok`. Затем `init` запускает лаунчер.
3. Экран: чёрный фон, вкладки «Продолжить · Игры · Настройки · Модули · Файлы ·
   Сведения», статус-бар с часами и батареей. При выводе первого кадра в консоли
   появляется `DEEPoS: launcher first frame`.
4. Для лога от включения подключите UART-адаптер к площадкам платы и выставьте
   `1500000 8N1`, без управления потоком. Это скорость `console=ttyS2,1500000n8`
   данной сборки. USB ACM (§0.7) появляется после запуска `rcS`.
5. Если экран тёмный, последняя строка UART отделяет ошибки загрузчика,
   монтирования корня и видеовывода. Для панели сверить `FDT` и прочитать `dmesg`.

## 4. Чек-лист приёмки (отмечать по факту)

### 0.40 на R36S‑V20

- [ ] Включить USB-сеть через порт OTG. ПК обнаруживает адаптер. Включить DHCP на хосте и сверить адрес на плитке с выданной арендой. Отключить режим, убедиться, что адаптер исчез.
- [ ] Включить USB-файлы, скопировать тестовый ROM и безопасно извлечь ROMS на ПК. Вернуть режим кнопкой A и запустить игру из новой папки.
- [ ] Изменить параметры RetroArch, запустить игру и сверить FPS, масштаб и сглаживание. Вернуть «Из RetroArch» и проверить сохранность исходного файла настроек.

### 0.39 на R36S‑V20

- [ ] Включить консоль с холодного старта, убрать руки с кнопок. После инициализации панели должен появиться логотип DEEPoS, затем меню. Проверить три запуска и отсутствие текста консоли поверх меню.
- [ ] Сравнить читаемость Terminus, подсказок и длинных названий со стабильной картой. Сверить видимые 640×480 и отсутствие обрезания по периметру.
- [ ] Проверить звуки смены вкладки, подтверждения и возврата в динамике и наушниках. Стрелки при листании списка и обновление мониторинга должны проходить тихо. Проверить, что звук RetroArch запускается сразу после меню.
- [ ] Из **Настройки → Управление** проверить стрелки, A/B/X/Y, L1/R1/L2/R2, Select, Start, FN, стики и качельку громкости. Для сырых кодов создать `INPUT.PROBE` на BOOT, перезагрузить, нажать кнопки в течение 40 секунд и сохранить `report/input.txt`.
- [ ] Изменить яркость, громкость и профиль CPU. Проверить эффект на устройстве и восстановление после перезагрузки. Сверить предел профиля с `/sys/devices/system/cpu/cpufreq/policy0/scaling_max_freq`.
- [ ] Проверить обновление температуры, RAM, CPU/GPU и батареи в **Сведениях**. Для непрочитанных датчиков сохранить sysfs и журнал драйвера.
- [ ] Открыть **Модули** из настроек. Проверить возврат B на плитку, переход к профилю CPU и создание копии сейва.
- [ ] Установить комплект по [EMULATORS.md](EMULATORS.md). По каждой системе зафиксировать ROM/формат, ядро, загрузку, звук, ввод и сохранение. Проверить Select + Start в каждой игре RetroArch, возврат к выбранной системе и повторный запуск.

### Базовая приёмка

- [ ] Панель: картинка без полос, разрешение 640×480, поворот 0.
- [ ] Подсветка: 46 уровней, `default-brightness-level = 38`, регулировка работает.
- [ ] Кнопки: 16 GPIO-кнопок, A/B в правильном порядке (оверлей `ABs` не нужен —
      DTS сразу описывает физическую раскладку).
- [ ] Стики: 4 аналоговых оси, мёртвая зона не «плывёт», fuzz/flat работают.
- [ ] Громкость: качелька ADC, звук в динамике (spk-con-gpio gpio3 7).
- [ ] Питание: `battery` в sysfs, проценты меняются, зарядка видна при кабеле в
      гнезде CHARGE (OTG — только данные).
- [ ] Нагрев: простой ≤55 °C, стресс 4 потока 5 мин ≤85 °C, троттлинг срабатывает.
- [ ] Память: `MemAvailable` в простое ≥560 МБ, `MemTotal` ≈732 МБ.
- [ ] До строки `DEEPoS: launcher first frame` по UART проходит ≤12 с.
- [ ] Проверить A → B → A на тестовой карте. Выполнить `updatr --state /data --boot /flash switch B`,
      перезагрузиться, затем выполнить `updatr --state /data --boot /flash switch A` и
      снова перезагрузиться. Сверить фактический корень и `attempts=0` после первого кадра.
- [ ] На тестовой карте собрать слот B с лаунчером, завершающимся до первого
      кадра. На каждой загрузке B счётчик растёт, после четвёртой `slot=A` и
      `rollback=true`. Перезагрузиться в A и проверить сброс счётчика после первого
      кадра. Сверить заранее сохранённые контрольные файлы на DATA и ROMS.
- [ ] После запуска `modd` проходит `test -S /run/modd.sock`, `thermal` показывает
      температуры, `saves` делает бэкап.
- [ ] Samba/USB: `smbd` поднимается, `\\deepos\...` виден с ПК; gadget NCM даёт
      SSH root@deepos.local.
- [ ] Сейвы: `saved put` → перезагрузка → `saved get` возвращает тот же файл.

## 5. Если что-то пошло не так

| Симптом | Что проверить |
|---|---|
| Нет картинки, UART молчит | загрузчик: смещения `idbloader`/`u-boot.itb`, питание карты, целостность `BOOT` |
| UART есть, экран тёмный | DTB/панель: `panel@0` compatible, `reset-gpios`, тайминги, `dsi,lanes` |
| `root=PARTLABEL=DEEPOS_A` не найден | GPT: метка `DEEPOS_A`, размер squashfs, `mkimage` не обрезал раздел |
| Экран есть, лаунчер падает | `journalctl` нет (нет systemd) → смотреть `/tmp/launcher.log`, свободную RAM, размер шрифтов |
| Троттлинг раньше 85 °C | `thermal_zone` trip-точки, `cooling-maps`, термопрокладка |
| Кнопки перепутаны | `gpio-keys` code/GPIO в DTS, `linux,code` из `linux-event-codes.h` |

## 6. Возврат на Arch-R

Образ Arch-R (`images\ArchR-clone.img.gz`, 1.6 ГБ) + оверлей панели остаются в
локальной папке проекта: перепрошить тем же `dpflash.py` или Etcher,
вернуть оверлей `mipi-panel.dtbo` и настройки из бэкапа. Данные ROM лежат на
отдельном exFAT-разделе, при перепрошивке их нужно сохранить заранее.

## 7. Отчёт с устройства (после первого буста)

Собрать факты в один файл, чтобы сравнивать с host-эталоном из `docs/PROTOTYPE-STATUS.md`.
Команды выполняются на консоли (UART или SSH через USB-NCM, `root@deepos.local`):

```sh
# 1. Базовая готовность
/usr/bin/launcher --selftest

# 2. Диски и монтирования
cat /proc/cmdline
awk '$5 == "/" && / - squashfs / { print; exit }' /proc/self/mountinfo
cat /proc/mounts
ls -l /flash/report/boot.txt /flash/report/mounts.txt /flash/report/checks.txt
df -h

# 3. Память (цель: MemAvailable >= 560 МБ, MemTotal ~732 МБ)
free -m
cat /proc/pressure/memory

# 4. Температуры и частоты
for z in /sys/class/thermal/thermal_zone*/type; do echo "$z: $(cat $z) $(cat $(dirname $z)/temp)"; done
cat /sys/devices/system/cpu/cpufreq/policy0/scaling_cur_freq
cat /sys/devices/system/cpu/cpufreq/policy0/scaling_governor

# 5. A/B и модули
/usr/bin/updatr --state /data --boot /flash status
test -S /run/modd.sock && ls -l /run/modd.sock
ls /data/modules

# 6. Питание
grep . /sys/class/power_supply/battery/{status,capacity,voltage_now,charge_full,charge_full_design}

# 7. Загрузка (что успело сказать ядро и rcS)
dmesg | grep -iE "mmc|panel|st7703|rk817|gadget" | head -40
dmesg | head -3
```

Прислать вывод целиком — по нему заполняется `docs/device-report.md`:

| Что | Эталон host | Факт на устройстве |
|---|---|---|
| `launcher --selftest` | `status=ok`, `systems=…`, `data_ok=1`, `roms_ok=1` | |
| Загрузка до первого кадра | ≤ 12 с | |
| `MemAvailable` в простое | ≥ 560 МБ (Arch-R: 414–468) | |
| Простой, °C | 48–53 | |
| Стресс 4 потока 45 с, °C | 1296 → ~70, 1416 → 79.6 | |
| Троттлинг | порог 85 °C | |
| A/B | `attempts=0..2`, слот A | |
| `modd` + модули | thermal/saves в списке | |

Если расхождение по экрану/кнопкам/звуку — сначала смотреть таблицу «Если что-то пошло
не так» (§5), затем присылать `dmesg` и `--selftest`: по этим двум выводам видно,
DTB-проблема это, драйвер панели или userland.


### 0.6. Отчёт о загрузке, если нет UART и SSH

Лаунчер и `rcS` пишут отчёт в `BOOT/report/` (`boot.txt`, `mounts.txt`, `free.txt`, `dmesg.txt`,
`temps.txt`, `cpufreq.txt`, `modules.txt`, `selftest.txt`). Забрать отчёт с ПК:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\pull-report.ps1
```

Файлы появятся в `build/device-report/`. Это же — основа для §7: вставьте содержимое
`boot.txt`, `temps.txt`, `free.txt` и `selftest.txt` в отчёт.


### 0.7. USB-консоль вместо UART

После загрузки DEEPoS на OTG-кабеле поднимаются две функции gadget: CDC-ACM (COM-порт) и
NCM (сеть `<console-ip>/16`). Для виртуального COM-порта используйте `115200 8N1`,
без управления потоком. Параметры UART-адаптера для лога от включения указаны в §3.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\usb-shell.ps1
# затем
plink -serial COMx -sercfg 115200,8,n,1,N          # интерактивно, login root, без пароля
plink -serial COMx -sercfg 115200,8,n,1,N -batch -m tools\report-commands.sh
```

Вердикт первого буста лежит в `BOOT/report/checks.txt` (`verdict=PASS|FAIL`, `panel=`, `data=`,
`input_events=`, `mem_available_mb=`). После первого кадра отчёт обновляется с `launcher=running`.
