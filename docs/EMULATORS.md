# Эмуляторы DEEPoS для R36S‑V20

## Образ с предустановленными эмуляторами

В образе 0.39 с комплектом RetroArch бинарный файл, ядра, библиотеки и профиль
геймпада уже размещены в `/data/emus`. На тестовой карте после первого запуска
достаточно положить свои ROM в папку системы на `ROMS`. Контент можно держать
в корне раздела (`/storage/gba`) или под `/storage/roms/gba`.

При сборке укажите `RETROARCH_PACKAGE` с путём к архиву для
[`tools/build-v20-image.sh`](../tools/build-v20-image.sh). Скрипт добавит комплект
в начальное содержимое DATA. Для обновления системы через A/B комплект можно
установить отдельно по инструкции ниже.

## Установка комплекта на существующую систему 0.39

Тестовая сборка 0.39 запускает RetroArch из `/data/emus`. Комплект собирается
локально из Arch‑R Clone с AArch64-ядрами, системными библиотеками, Mesa и
профилем встроенного геймпада. Подготовленный архив можно перенести через ROMS.

1. На ПК скопируйте `deepos-retroarch-v20.tar.gz` в корень раздела `ROMS`.
2. Загрузите 0.39 и в оболочке консоли проверьте, что `/data` смонтирован как
   ext4 с правом записи и на нём хватает места для распаковки (`df -h /data`).
3. Если `/data/emus` уже существует, сохраните эту установку отдельно. Для
   первой установки выполните:

   ```sh
   test ! -e /data/emus && mkdir /data/.emu-install &&
       tar -xzf /storage/deepos-retroarch-v20.tar.gz -C /data/.emu-install &&
       mv /data/.emu-install/emus /data/emus && rmdir /data/.emu-install
   ```

4. Положите свои игры в `/storage/<система>/`, например `/storage/gba/`.
   BIOS, который требуется конкретному ядру, положите в `/storage/bios/`.
5. Откройте **Игры**, выберите систему и игру, нажмите **A**. **Select + Start**
   штатно закрывает RetroArch и возвращает в DEEPoS. **L1 + R1** открывает меню
   RetroArch. Сейвы и состояния по умолчанию находятся в
   `/storage/.config/retroarch/saves` и `/storage/.config/retroarch/states`.

Для 0.38 нужны команда из нового реестра, скрипт запуска и оба файла конфигурации
из 0.39. Проще проверить комплект с новым rootfs на отдельной карте.

## Как собрать комплект из Arch‑R Clone

В Linux с `debugfs`, Python 3 и `pyelftools` или внутри `deepos-cross:local`:

```sh
python3 tools/import-retroarch.py --donor /path/to/ArchR-clone.img.gz \
    --out build/deepos-retroarch-v20.tar.gz
```

Скрипт читает второй раздел образа, проверяет формат AArch64 ELF и собирает
ядра из `board/r36s-v20/data/emulators.toml` и каталога `/usr/share/archr/systems.cfg`
вместе с их `DT_NEEDED`. `emus/systems.toml` содержит команды для систем с
подходящим ядром, `emus/extensions.tsv` — их расширения ROM. В
`emus/unmapped.txt` перечислены строки каталога, для которых требуется
другая интеграция.
Для отдельных ядер можно повторять `--core`. Для повторной локальной сборки
можно передать извлечённый раздел через `--root-ext4`. Временное извлечение
занимает до размера раздела Arch‑R (в проверяемом образе 6 ГиБ).

## Реестр систем

В локальном комплекте для 0.39 собраны 76 ARM64-ядер и 112 записей из
124 записей Arch‑R. В архиве перечислены оставшиеся записи в `unmapped.txt`.
`ports` обслуживается отдельной командой DEEPoS. Критерий приёмки каждой
системы — запуск игры на R36S‑V20 с работающими звуком, управлением и выходом.

- Базовые системы и алиасы перечислены в
  [`board/r36s-v20/data/emulators.toml`](../board/r36s-v20/data/emulators.toml).
  Это же источник для списка импортируемых ядер. Выбор ядра можно переопределить
  в `/data/emulators.toml`. `%ROM%` передаёт путь к игре одним аргументом.
- Для PSP, Nintendo DS, N64, Dreamcast и Saturn в реестре предусмотрены
  libretro-ядра. Требуется проверить запуск, частоту кадров, звук, сохранение и
  кнопки по каждой платформе. Для PSP, NDS и аркад учитывайте требования ядра к
  дополнительным ресурсам, BIOS и версии romset.
- Весь каталог из 175 систем остаётся критерием K3. Для платформы, которой нет
  в реестре, добавьте команду с именем папки ROM. Совместимому standalone нужны
  собственные библиотеки и профиль ввода. Select + Start настроен для RetroArch;
  отдельному эмулятору нужна поддержка комбинации в его настройках.

Пример пользовательской записи для GBA:

```toml
gba = "/usr/local/bin/retroarch-game.sh mgba %ROM%"
```

Для диагностики запустите `launcher --run-game 'gba:Game.gba'`. Код 5 означает,
что отсутствует подходящая команда или исполняемый файл/ядро. Код 1 означает
ошибку выполнения эмулятора. Сохраните вывод терминала для диагностики.

Источники. [Режим KMS в RetroArch](https://docs.libretro.com/guides/kms-mode/),
[настройки RetroArch и комбинации кнопок](https://github.com/libretro/RetroArch/blob/master/retroarch.cfg),
[профили контроллеров](https://docs.libretro.com/guides/controller-autoconfiguration/).
