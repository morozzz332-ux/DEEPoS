# R36S / R36S-клон: прошивка, USB и доводка — проверенная инструкция

Документ написан по реально пройденному пути на конкретной консоли (плата `R36S-V20 2025-05-18`).
Всё, что здесь есть — проверено руками; тупиковые варианты вынесены в конец, в раздел «Чего не делать».

---

## 0. Что это за устройство

| Параметр | Значение |
|---|---|
| SoC | Rockchip RK3326, 4× Cortex-A35 до 1.4 ГГц |
| GPU | Mali-G31 MP2 |
| RAM | 1 ГБ LPDDR3 (в системе видно ~731 МБ) |
| Экран | 640×480, панель Sitronix ST7703 |
| Питание | PMIC RK817 (заряд + топливомер) |
| Батарея | Li-Po 3.7 В, 3500 мА·ч (804068) |
| Накопитель | **microSD, eMMC нет** — вся система на карте |

Два разъёма: **OTG** (данные, USB-C) и **CHARGE** (только питание, 5 В ≥ 1.5 А).
Зарядка через OTG не идёт — это норма, а не поломка.

---

## 1. Первое: определить, оригинал или клон

От этого зависит вариант образа. Клоны собраны на другой пайке панели и кнопок.

1. Снять заднюю крышку (4 винта) и прочитать шелкографию платы.
2. `R36S-V20` / `R36S-V21` и дата вида `2025-05-18` — **клон** (в сообществе помечены как clone/untested).
   Оригинал обычно `R36S-V1.x` без «20».
3. Дополнительно: в системе клон часто показывает **731 МБ** RAM вместо 1 ГБ (одна планка памяти).

Запомни результат: **оригинал → образ `original`**, **клон → образ `clone`**.

---

## 2. Бэкап стоковой системы (делать всегда)

Вариант А, самый простой (рекомендую новичкам):
- Вставить карту в картридер, скопировать **обе видимые папки** (`BOOT` и `EASYROMS`) на компьютер.
  Этого достаточно, чтобы вернуть игры и настройки.

Вариант Б, полный образ (для восстановления всей системы):
- `Win32DiskImager` → **Read** с карты в файл `stock-r36s.img` (займёт столько же, сколько объём карты).
- Дополнительно сохранить `BOOT/rf3536k3ka.dtb` (или другое имя `*.dtb`) — он понадобится для оверлея панели.

> Карта 50 ГБ → образ ~50 ГБ. Место проверяй заранее.

## 3. Выбор прошивки

| Прошивка | Кому | Почему |
|---|---|---|
| **ArchR** | тем, кто хочет «покопаться» | Arch Linux, ядро 6.12 LTS, pacman, USB-сеть по одному кабелю, SSH, нормальные логи |
| ArkOS / dArkOS | тем, кто хочет «просто играть» | проще, но USB-сети нет (SSH только по Wi-Fi) |
| ROCKNIX | альтернатива | своя сборка, другой набор эмуляторов |

Ниже — ArchR. Ссылки: `arch-r.io`, `github.com/archr-linux/Arch-R`, документация `arch-r.io/docs/`.

## 4. Прошивка карты

### 4.1 Скачать

- Образ: `ArchR-R36S.aarch64-<дата>-clone.img.gz` (~1.5 ГБ) — для клона, `original` — для оригинала.
- Проверить SHA256 по `SHA256SUMS` (PowerShell: `Get-FileHash файл -Algorithm SHA256`).
- Флешер (необязательно): **ArchR Flasher** (portable `.exe`) или **balenaEtcher**.

### 4.2 Подготовить оверлей панели (обязательно!)

Образ **не содержит** правильного описания панели: без оверлея экран останется чёрным.

1. Взять стоковый DTB со своей карты (`BOOT/rf3536k3ka.dtb`).
2. Скачать `archr-dtbo-offline.zip` (офлайн-генератор) или открыть `arch-r.io/overlay-generator`.
3. Сгенерировать:

```bash
python archr_dtbo.py rf3536k3ka.dtb SDCLONE -o mipi-panel.dtbo     # клон
python archr_dtbo.py rf3536k3ka.dtb SDORIG  -o mipi-panel.dtbo     # оригинал
```

Полезные флаги:
- `SDCLONE-ABs` — если **кнопки A и B перепутаны** (физическая B определяется как A);
- `--safe-cpu` — ограничить CPU 1296 МГц (меньше тепла и расхода);
- без `--safe-cpu` — 1416 МГц (быстрее, греется сильнее).

4. Положить файл на карту: `<FAT-раздел>/overlays/mipi-panel.dtbo`.

### 4.3 Записать образ

**Простой путь:** balenaEtcher → Select image → Select drive → Flash. Etcher сам размонтирует тома.

**Если Windows ругается «Access denied / Error 5»:** это не права, а смонтированные разделы.
Закрой проводник, сними буквы дисков в «Управлении дисками» или используй Etcher. Продвинутый
вариант, который работает всегда: писать образ своим writer'ом, **откладывая MBR (сектор 0) до конца** —
пока MBR нулевой, Windows ничего не монтирует и запись не блокируется.

### 4.4 Перед первым включением

- Убедиться, что `overlays/mipi-panel.dtbo` на месте.
- В `extlinux/extlinux.conf` должна быть строка `FDTOVERLAYS /overlays/mipi-panel.dtbo`.
- Вставить карту, включить, **не выключать** на первом бусте: система расширит корень, создаст
  exFAT-раздел `ARCHR_ROMS` на всё свободное место и **сама перезагрузится**. Это нормально.

> После прошивки метки разделов меняются: `ARCHR` (FAT, 256 МБ) и `ARCHR_ROMS` (игры).
> Старых `BOOT`/`EASYROMS` больше нет — это ожидаемо.

## 5. Первичная настройка

1. `Settings → Region and language`: язык — **Русский**, таймзона, 24-часовой формат.
2. `Settings → Controls → Test controller`: проверить кнопки и стики (Y на экране — калибровка стиков).
   Если A/B перепутаны — см. п. 7.1.
3. `Settings → Network → Network services`:
   - `Режим USB (gadget)` = **Сеть (NCM)**;
   - `SSH` = вкл;
   - `Пароль root (SSH)` — сменить с `archr` на свой;
   - Samba и «Простой HTTP-сервер» — по желанию.
4. Батарея: сделать один полный цикл (см. п. 8).

## 6. USB: три режима и как ими пользоваться

Кабель в **OTG**, консоль в меню `Сетевые службы`:

| Режим | Что даёт | Как выглядит на ПК |
|---|---|---|
| `Сеть (NCM)` | сеть между ПК и консолью: **SSH, Samba, HTTP** | новый Ethernet-адаптер `UsbNcm Host Device` |
| `Интернет от ПК` | то же + выход в интернет через ПК | тот же адаптер + шаринг/NAT на ПК |
| `Передача файлов` | MTP-доступ к `ARCHR_ROMS` | «Переносное устройство» без буквы диска |

Переключение режима **всегда** рвёт SSH — это норма.

### 6.1 Адреса (запомнить)

- Без интернета: консоль **<console-ip>**, ПК получает `169.254.x.x` автоматически.
- С шарингом: ПК **<pc-ip>**, консоль `192.168.137.x`.
- Поле «Адрес по USB» в меню показывает **статический адрес из конфига**, а не фактический.
  Проверять реально: `ip addr`, `ip route` по SSH.

### 6.2 SSH

На консоли включить SSH. На ПК — любой клиент (PuTTY, Windows Terminal `ssh`):

```powershell
ssh root@<console-ip>        # пароль из меню (по умолчанию archr)
ssh root@archr.local          # если mDNS работает
```

Для скриптов удобен plink:

```powershell
plink -ssh -batch -pw <пароль> -hostkey <отпечаток> root@<console-ip>
```

`-hostkey` нужен только для неинтерактивных вызовов: один раз запусти без него, PuTTY покажет
отпечаток (`ssh-ed25519 SHA256:...`), его и подставляй.

### 6.3 Интернет консоли через ПК (правильный способ)

1. Консоль: `Интернет от ПК`.
2. ПК: включить общий доступ к интернету на USB-адаптере консоли
   (`Свойства адаптера → Доступ → Разрешить другим пользователям…`). Если статус на консоли
   остаётся «ПК не раздает интернет» — ICS не поднялся, идём шагом 3.
3. Надёжная альтернатива — **WinNAT** (Windows 10/11 Pro; в PowerShell от администратора):

```powershell
New-NetNat -Name ConsoleNat -InternalIPInterfaceAddressPrefix 192.168.137.0/24
netsh interface ipv4 add address name="Ethernet 4" address=<pc-ip> mask=255.255.255.0
netsh interface ipv4 add address name="Ethernet 4" address=<pc-ip>   mask=255.255.0.0
```

4. На консоли (по SSH):

```bash
ip addr add <console-ip>/24 dev gadget
ip route replace default via <pc-ip> dev gadget
resolvectl dns gadget 1.1.1.1 8.8.8.8
resolvectl domain gadget '~.'
```

5. Проверка: `ping 1.1.1.1`, `curl -I https://example.com`.
   Пинг самого шлюза `<pc-ip>` может не отвечать — Windows блокирует ICMP, на интернет это не влияет.

### 6.4 Чтобы не настраивать после каждого переподключения

- На консоли: служба + таймер, которые раз в 30 с возвращают адрес/маршрут:

```bash
mkdir -p /etc/systemd/system
cat > /usr/local/bin/net-console.sh <<'EOF'
#!/bin/sh
ip addr show dev gadget | grep -q '<console-ip>' || ip addr add <console-ip>/24 dev gadget
ip route show default | grep -q '<pc-ip>' || ip route replace default via <pc-ip> dev gadget
resolvectl dns gadget 1.1.1.1 8.8.8.8
EOF
chmod +x /usr/local/bin/net-console.sh
```

- На ПК: скрипт с `netsh interface ipv4 add address ...` — запускать после каждого переподключения кабеля
  (вторичные адреса адаптера теряются при ре-энумерации).

### 6.5 Файлы: SMB вместо MTP

MTP годится для пары файлов, для библиотеки — SMB:

```powershell
net use \\<console-ip>\games-roms /user:root <пароль>
robocopy D:\Games\psp \\<console-ip>\games-roms\psp /Z /R:3 /W:5 /MT:4
```

`/Z` — докачка при обрыве. **Не копировать одним длинным потоком:** NCM-канал рвётся на файлах
больше ~100 МБ; `/MT` + `/Z` переживают обрывы.

## DEEPoS 0.39 на R36S‑V20

В **Настройках** нажмите A на плитках «Дисплей», «Звук» или «Питание» для
смены значения. Значение сохраняется в DATA. Сообщение на экране указывает,
если драйвер не применил изменение. Вкладка **Сведения** показывает реальный
предел CPU, частоты, температуру, память и батарею. Её можно открыть кнопкой Select.

Для установки RetroArch, ядер и профиля геймпада используйте
[инструкцию по эмуляторам](EMULATORS.md). Выход из игры в RetroArch — Select + Start.

### USB и модули в DEEPoS 0.40

- **USB-сеть.** Подключите кабель передачи данных к OTG и включите плитку USB-сети.
  Компьютер должен раздавать параметры через DHCP. Например, в Windows включите
  общий доступ к интернет-подключению для появившегося USB-адаптера. Полученный
  адрес появится на плитке. При прямом подключении без DHCP она показывает ожидание.
- **USB-файлы.** Нажмите A на плитке USB-файлов. На ПК должен появиться диск ROMS.
  После копирования используйте безопасное извлечение на ПК и снова нажмите A,
  чтобы вернуть том лаунчеру. DATA с настройками и сейвами в этот режим не входит.
  Если ядро отклонило режим, используйте картридер для раздела ROMS.
- **Новые модули.** [Исходники штатных модулей](https://github.com/morozzz332-ux/DEEPoS/tree/main/modules)
  показывают структуру `module.toml` и `main.sh`. Модули устанавливаются вручную
  с Linux или из оболочки консоли в `/data/modules/<id>/`, затем перезапускается
  DEEPoS. Сценарию нужен исполняемый бит. Устанавливайте только проверенный код,
  поскольку модули выполняются с правами системной службы.

## 7. Доводка железа и системы (ArchR)

### 7.1 Перепутанные A/B

Причина — пайка клонов. Правильное лечение — **DTB-оверлей с флагом `ABs`** (п. 4.2), он правит
раскладку на уровне драйвера, и кнопки становятся верными во всех эмуляторах и портах.
Установка: `mount -o remount,rw /flash`, скопировать файл в `/flash/overlays/mipi-panel.dtbo`,
`sync`, `mount -o remount,ro /flash`, перезагрузка. Старый файл сохранить как `*.bak`.

### 7.2 Батарея: проценты врут

Топливомер RK817 (кулоновский счётчик) сбивается после глубокого разряда. Лечение:

```bash
# 1. один полный цикл: заряд до 100% + 1-2 часа сверху, затем разряд до автоотключения, затем полный заряд
# 2. выставить реальную ёмкость банки (мкА·ч)
echo 3500000 > /sys/class/power_supply/battery/charge_full
cat /sys/class/power_supply/battery/capacity
```

Узел называется **`battery`**, не `rk817-battery`. Поля: `capacity`, `charge_full` (rw),
`charge_full_design` (ro), `voltage_avg`, `current_avg`.
Если `charge_full_design` = 4000000, а банка 3500 мА·ч — это нормально, важен `charge_full`.

### 7.3 Нагрев и частота

- Порог троттлинга — **85 °C** (trip point `passive`), critical 115 °C.
- 1416 МГц (без `--safe-cpu`): стресс 4 потока даёт ~80 °C — допустимо, но в долгих 3D-играх ощутимо.
- 1296 МГц (`--safe-cpu`): ~70 °C, +15–20 мин работы от батареи.
- **1512 МГц недоступны**: в ядре нет `cpufreq/boost`, `vdd_arm` ограничен 1.35 В. Не тратить время.
- Быстрый выбор профиля (если поставлен скрипт): `cpu-profile eco|balanced|max`.
- Железо: термопрокладка 1–1.5 мм от SoC к задней крышке; дрелью — 2–3 отверстия над SoC;
  **микро-вентилятор не ставить** (шум и пыль без выигрыша); металл — не над батареей.

### 7.4 Память

- Один процесс максимум ~450 МБ, дальше OOM. CMA — 32 МБ.
- zram: `archr-memory-manager --zram-size 1536` (в `swap.conf`), затем `--reload`.
  Основной алгоритм останется `lzo-rle` — это задумано, zstd работает на пересжатии; руками не менять.
- Для тяжёлых игр закрывать лишнее: `systemctl stop smbd simple-http-server` перед запуском.

### 7.5 Обновления

```bash
tar czf /storage/backup/flash-$(date +%Y%m%d).tar.gz -C / flash   # бэкап загрузчика
archr-update check
archr-update update --progress     # затем перезагрузка
```

После обновления проверить: оверлей на месте, `extlinux.conf` цел, `pacman -Q linux archr`.

### 7.6 Порты (PC-игры)

```bash
sh -c '. /usr/bin/portmaster_prepare'          # один раз, распаковывает PortMaster
cd /storage/roms/ports/PortMaster
./harbourmaster install quake.zip --quiet
```

Запуск — раздел `Ports` в лаунчере. Файлы игр (`.wad`, `pak0.pak`, `DIABDAT.MPQ`) кладутся в папку порта.

### 7.7 Скорость эмуляторов

- **PPSSPP**: 1× разрешение, OpenGL, auto frameskip, «disable slower effects» — 30 FPS реально.
- **Flycast**: 240p, threaded rendering.
- **N64**: mupen64plus, разрешение 1×, без текстур-паков.
- **PS1**: DuckStation, 1×–2×, можно шейдер CRT.
- Тяжёлое 3D (Saturn, PSP-блокбастеры) — не мучить.

## 8. Чего не делать

| Не делать | Почему |
|---|---|
| Прошивать консоль по USB | нельзя, образ пишется только на карту |
| Искать adb | в ArchR его нет, доступ — SSH |
| Ставить `--safe-cpu` оверлей «на всякий случай» вместе с `ABs` | это разные флаги одного файла: собрать **один** с обоими (`SDCLONE-ABs --safe-cpu`) |
| Включать RNDIS («Совместимость с Windows 10») | на этом ядре gadget не пересобирается: `Could not build the network gadget` |
| Писать в `/flash` без `mount -o remount,rw` | раздел смонтирован ro, запись молча не пройдёт |
| Дёргать `comp_algorithm` у zram | менеджер откатит, это штатное поведение |
| Копировать 10 ГБ одним потоком по USB | NCM рвётся >100 МБ, использовать `robocopy /Z` или SMB |
| Форматировать внешний диск с бэкапом | это единственная копия игр |
| Ставить «ускорители» с GitHub (CPU-Manager и т.п.) | дублируют `ajuste-cpu` и штатные профили, риск конфликта |

## 9. Быстрая диагностика

| Симптом | Причина | Решение |
|---|---|---|
| Чёрный экран после прошивки | нет оверлея панели | положить `overlays/mipi-panel.dtbo`, проверить `FDTOVERLAYS` |
| SSH: `Network is unreachable` | у адаптера на ПК нет адреса | задать `<pc-ip>/16` и `<pc-ip>/24` через `netsh` |
| Консоль «ПК не раздает интернет» | ICS не поднялся | WinNAT + адреса вручную (п. 6.3) |
| Нет пакетов от консоли вообще | gadget завис | `pnputil /remove-device "USB\VID_1D6B&PID_0104\..."` + передёрнуть кабель |
| Сессия рвётся на копировании | NCM под нагрузкой | `robocopy /Z`, копировать папками по 1–2 ГБ |
| `WriteFile failed win32=5` при прошивке | Windows смонтировал разделы | Etcher или writer с отложенным MBR |
| Проценты батареи скачут | сбитый кулоновский счётчик | полный цикл + `charge_full` |
| Игры пропали после прошивки | карта отформатирована | вернуть из бэкапа в `/storage/roms` |
