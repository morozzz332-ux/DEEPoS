# R36S-V20 · Спецификация собственной прошивки (MVP)

**Версия:** 1.2 · **Дата:** 2026-11-20 · **Заменяет:** 1.1 (`FIRMWARE-ARCH.md` остаётся историей решений)
**Железо:** клон `R36S-V20 2025-05-18` (SoC RK3326, PMIC RK817, панель ST7703, 1 ГБ LPDDR3)
**Документ рассчитан на:** агента-разработчика, который по нему начинает и ведёт MVP без дополнительных уточнений.

---

## 0. Как агенту пользоваться этим документом

1. Прочитать §1 (концепция), §13 (этапы), §17 (правила работы). Только потом — код.
2. Работать строго по этапам §13: этап считается сданным, когда пройдены его тесты из §14 и сняты метрики.
3. Любое отклонение от спецификации — сначала правка этого документа (коммит `docs: spec change …`), потом код.
4. Запреты (§17.4): не писать в BootROM/DDR-инициализацию, не менять разделы пользователя без бэкапа, не добавлять пакеты «на всякий случай», не превращать ядро в Arch-R.
5. Сомнение в цифре — проверять на устройстве (`/sys`, `dmesg`, `rc`, `journalctl`), а не по памяти. Всё, что не измерено, помечать `[проверить]`.

## 1. Концепция и инварианты

Новая прошивка делается под четыре жёстких инварианта. Нарушение любого = провал итерации.

| # | Инвариант | Измеримое требование |
|---|---|---|
| **K1** | Система не грузит железо | idle: RSS userland **≤ 150 МБ** (из 732), загрузка **≤ 12 с** до первого кадра, **≤ 6** постоянно живущих демонов, CPU в простое ≤ 2 % |
| **K2** | Тяжёлые игры без вылетов и фризов | нет `oom-kill` ни в одном сценарии §14; PSI `memory.full avg10` в игре < 5 %; кадровый разрыв > 250 мс не более 1 на 10 минут; PSP-3D держит целевой FPS из §11 |
| **K3** | Поддержка всех консолей, что были | все системы из реестра §9.1 запускаются; для каждой — ядро есть и проверено на 1 игре минимум |
| **K4** | Обратная совместимость | ROM/образы, `gamelist.xml`, сейвы и стейты, конфиги RetroArch, порты PortMaster читаются без конвертации (§16) |

**Целевой профиль системы:** «тощая оболочка + эмуляторы». Никаких фоновых индексаторов, обновлятелей экрана и сетевых служб в игре.

## 2. Железо и его реальные пределы

| Узел | Факт | Предел / нюанс |
|---|---|---|
| SoC | Rockchip RK3326, 4× Cortex-A35, 32-бит LPDDR3-контроллер | OPP: 408 / 816 / 1008 / 1416 МГц |
| CPU turbo | 1512 МГц существует как OPP, но выключен | нужен `cpufreq/boost` + `vdd_arm` 1.40 В (сейчас max 1.35 В). **Не входит в MVP**, только эксперимент §15 |
| GPU | Mali-G31 MP2 (Bifrost G31), OPP 200 / 300 / 400 / 650 МГц | 650 — турбо; выше OPP в DTB нет |
| RAM | 1 ГБ LPDDR3, один чип **Nanya `NT6CL256M32-H1`** (ревизия V20; у части плат — XINYUEI `XT26S6M3Z0M-HI`) | апгрейд только BGA-пайкой + правка DDR-init; в проекте не планируется |
| Экран | 640×480 MIPI-DSI, контроллер **Sitronix ST7703**, reset — **GPIO3_B7** (active low) | инициализация DSI в DTS, панель как `panel-simple`/собственный драйвер |
| Питание/заряд | PMIC **RK817** (`rk817-battery`, `rk817-charger`), банка 804068 3.7 В **3500 мА·ч** (12.95 Вт·ч), LED: заряд `gpio0 17`, синий `gpio0 0` | кулоновский счётчик + OCV-рекалибровка; `charge_full` writable |
| Звук | кодек RK817 (SPKO), динамик + наушники (hp-det) | `rk817_codec`, простой sound card в DTS |
| Кнопки | ADC-клавиши + GPIO (D-pad, ABXY, L1/R1/L2/R2, SELECT/START, FN, Volume) | на клонах A/B перепутаны — правится оверлеем `ABs` или в DTS |
| USB | один порт **dwc2** OTG (480 Мбит), режимы peripheral/host | у V20 два гнезда: OTG — только данные, CHARGE — только питание |
| Носитель | только microSD (eMMC нет) | карта = система; UHS-режим проверить в `dmesg` |
| Связь | Wi-Fi/BT нет | только USB-донгл (RTL8188EU / RTL8723BU) или Ethernet через OTG-хаб |
| Отладка | UART-пэды `3.3V TX RX GND`, 115200 | консоль загрузки без пайки USB |
| Термика | trip: 70 °C passive, **85 °C passive (троттлинг)**, 115 °C critical | замеры: 1296 → ~70 °C, 1416 → **79.6 °C** (4 потока, 45 с), idle 48–53 °C |
| Батарея (время) | ~2.5–3 ч на Arch-R при 1416 | цель MVP: ≥4 ч MD, ≥2 ч PSP 2D |

## 4. Архитектура системы

### 4.1 Слои

```
┌──────────────────────────────────────────────────────────────┐
│ launcher  (C, KMS dumb-buffer, 1 UI-поток, 13–17 МБ)         │
│   ├─ screens: Продолжить / Игры / Настройки / Модули / Файлы / Сведения
│   └─ hosts: emulator runner, ports runner, scraper
├──────────────────────────────────────────────────────────────┤
│ svc  (supervisor: профили CPU/GPU, батарея, Bluetooth?, Wi-Fi)│
│  ├─ modd  (модули: JSON-RPC, cgroup, uid 61000–61999)         │
│  ├─ saved (сейвы/стейты/атомарность/resume)                   │
│  └─ netd  (USB gadget NCM/MTP, Samba по требованию)           │
├──────────────────────────────────────────────────────────────┤
│ busybox init (PID 1, /etc/inittab) + mdev                     │
├──────────────────────────────────────────────────────────────┤
│ Linux 6.12 LTS (mainline) + DTS r36s-v20 + overlays           │
├──────────────────────────────────────────────────────────────┤
│ U-Boot (idbloader+u-boot из Arch-R clone, проверен) → extlinux│
└──────────────────────────────────────────────────────────────┘
```

Решения (ADR, обоснование в `FIRMWARE-ARCH.md` §4):

- **ADR-001** Buildroot 2025.02 + mainline 6.12 LTS + **glibc** (нужна для бинарников PortMaster/эмуляторов) + busybox init/mdev. systemd не берём: −40–60 МБ и −2–4 с загрузки.
- **ADR-002** Без композитора. UI рисует в KMS dumb-buffer сам. Wayland/weston поднимается **только** на время порта, который его требует (`runemu`-обёртка), и гасится после выхода. Никакого постоянного sway.
- **ADR-003** Обновления A/B squashfs: `SYS_A`/`SYS_B` по 700 МБ, атомарное переключение в `extlinux`, автооткат при 2 неудачных бустах (счётчик в U-Boot env).
- **ADR-004** Данные и ROM отдельно от системы: `/data` (ext4, 1536 МиБ) и
  `ROMS` (exFAT, остальное место). Обновления системного слота сохраняют
  разделы DATA и ROMS.

### 4.2 Разделы карты (GPT, 32 ГБ минимум)

| # | Метка | ФС | Размер | Назначение |
|---|---|---|---|---|
| 1 | `BOOT` | FAT32 | 256 МБ | KERNEL, DTB, overlays, extlinux.conf, boot.scr, bootlogo |
| 2 | `SYS_A` | squashfs (ro) | 700 МБ | система A |
| 3 | `SYS_B` | squashfs (ro) | 700 МБ | система B (обновление/откат) |
| 4 | `DATA` | ext4 | 1536 МиБ | `/data`: конфиги, сейвы, стейты, модули, журналы |
| 5 | `ROMS` | exFAT | остаток | `/storage`: игры, BIOS, порты, обложки и входящие пакеты модулей |

Слот системы монтируется ro, `/data` и `/storage` rw с `noatime`.
Каталог `rom-folders.txt` определяет стандартные папки ROMS. TF2 сканируется
при загрузке отдельно от загрузочного MMC-устройства. Раздел с меткой
`ROMS`, `EASYROMS` или `GAMES` имеет приоритет. Файловые системы exFAT,
FAT32 и ext4 монтируются ro в `/games`. Библиотека группирует файлы обеих
карт по системе и сохраняет источник TF2 в истории запуска.

Регион хранится в `/data/config/clock` как идентификатор зоны IANA вместе с
последним подтверждённым временем UTC. При загрузке значение UTC применяется,
если системное время меньше сохранённого. Смена зоны переводит отображение
в местное время и оставляет системную шкалу UTC. При наличии RTC редактор
времени записывает его в UTC. При штатном выключении сохраняется последняя дата.

### 4.3 Загрузка (цель ≤ 12 с)

| мс | шаг |
|---|---|
| 0–300 | BootROM → TPL/SPL |
| 300–900 | U-Boot (без USB-перебора, `bootdelay=0`) |
| 900–2200 | kernel decompress + DSI init + панель |
| 2200–4500 | init/mdev, монтирование разделов, драйверы звука/питания |
| 4500–6500 | `saved` (рекавери), `modd`, чтение конфигов |
| 6500–8500 | launcher: кадр «Продолжить» (кеш обложек с диска) |
| 8500–12000 | фоновая предзагрузка обложек/скан новых ROM |

| SD | `dwmmc_rockchip`, UHS-SDR104 если карта позволяет | T1: скорость ≥ 20 МБ/с чтение |

Принцип: **всё нужное есть в mainline 6.12**; проприетарных блобов минимум (только libmali как альтернатива, по умолчанию — Panfrost).

## 6. UI: структура, визуальный язык, память

### 6.1 Разделы (постоянные вкладки, без анимаций)

1. **Продолжить** — до 12 недавних игр. A продолжает, X запускает без выбора слота.
2. **Игры** — сетка систем в две колонки и список игр. A открывает систему или запускает игру. B/Y возвращают к системам с фокусом на выбранной платформе.
3. **Настройки** — 12 плиток в три колонки. A меняет яркость, громкость, звуки меню, профиль CPU, режимы USB и параметры RetroArch. Модули, сведения и проверка управления открываются по A. B возвращает фокус на исходную плитку.
4. **Модули** — список от `modd`. A на `thermal` открывает профиль CPU. A на `saves` запускает создание резервной копии, результат виден в подсказке.
5. **Файлы** — сведения о томах и библиотеке. A на строке ROMS включает передачу файлов по USB и возвращает том после извлечения диска на ПК.
6. **Сведения** — текущая и предельная частоты CPU, частота GPU, температура, память, батарея, нажатая кнопка, uptime и версия. Измеряемые параметры обновляются раз в секунду на открытой вкладке. При отсутствии датчика отображается прочерк.

L1/R1 и L2/R2 перелистывают вкладки. Select и FN открывают сведения.
В RetroArch Select + Start закрывает эмулятор штатно, L1 + R1 открывает его меню.

**USB OTG в 0.40.** По умолчанию режим выключен. USB-сеть запрашивает IPv4,
маску, маршрут и DNS по DHCP у хоста. USB-файлы экспортирует только том ROMS,
отмонтированный на консоли. Запуск игры блокируется до возврата тома. Для
передачи файлов потребуется USB Mass Storage в ядре, для сети — NCM или RNDIS.

### 6.2 Визуальный язык (токены, 640×480)

```
bg      #08140A     panel   #102110     panel2  #1A3018     line  #38582D
fg      #D0F8A8     fg2     #A3DA7D     fg3     #82B368
acc     #B8F472     sel     #28431E     warn    #E6B25C     bad   #E0706A
```

- Безопасные отступы панели — 8 px сверху и 12 px снизу. Строка вкладок 32 px, заголовок 34 px, подсказка 28 px.
- Нативный буфер 640×480. Основной шрифт — Terminus Bold 8×16, подсказки — Terminus 8×14. Оба набора встроены как битовые таблицы. fbdev учитывает шаг строки, смещение и расположение цветовых каналов.
- На вкладке активен прямоугольник с инверсией фона и текста. В списках и плитках фокус обозначен зелёной полосой. Навигация L1/R1, подтверждение и возврат могут звучать короткими сигналами ALSA. Перемещение по строкам и фоновый мониторинг проходят тихо.
- После появления `/dev/fb0` `rcS` рисует логотип DEEPoS и затем запускает меню. Экранный VT переводится в графический режим. Журнал загрузки выводится через UART `ttyS2`.
- BMP для BOOT можно экспортировать из того же кадра командой `python3 branding/make-logo.py --launcher apps/launcher/launcher`. Ранний логотип DEEPoS отображается в Linux после готовности панели.
- Выделение — фон `sel` и полоса 3 px `acc`. Курсор статический.
- Кадр строится по событиям. На открытом экране мониторинга счётчики обновляются с частотой 1 Гц. В остальных вкладках без ввода сохраняется цель 0 кадров в покое.

### 6.3 Обложки = превью игры

Берём **существующее превью** (boxart/preview) и используем как иконку — отдельный арт не генерируем.

| Приоритет | Источник |
|---|---|
| 1 | локальные media: `media/covers/*`, `media/boxart/*`, `images/*`, `Named_Boxarts` / `Named_Snaps` / `Named_Titles`, `<rom>-image.*`, `<rom>-thumb.*`, `gamelist.xml` (`<image>`, `<thumbnail>`) |
| 2 | `thumbnails.libretro.com/<system>/Named_Boxarts|Named_Snaps|Named_Titles` — кэш на `ROMS`, докачка в фоне |
| 3 | скриншот сейва или `screenshots/` |
| 4 | плашка с инициалами |

- Вписывание `fit` в 4:3 без растяжения, поля — доминирующим цветом превью.
- Кэш: RGB565 96×72 = **13.8 КБ**/игру; в строке 34×26, в списке 24×18; LRU 32 ≈ **0.45 МБ**; предзагрузка 4–8 в простое.
- Скрапер встроенный: `scraper --missing-only --system <id>` (libretro-thumbnails), запускается вручную из «Файлы», не в игре.

## 7. Модульная система

Совместимость с API Arch-R `api_version 3` (чтобы `thermal`, `saves`, `ajuste-cpu` переносились почти без правок), но супервизор свой.

### 7.1 Протокол (NDJSON JSON-RPC по stdin/stdout)

| Направление | Метод | Таймаут | Ответ |
|---|---|---|---|
| launcher → модуль | `initialize` | 10 с | `{"ready":true}`, затем `ui.update` |
| launcher → модуль | `action.invoke` `{action, context}` | 1 с | `{}` |
| launcher → модуль | `launch.before` `{system, rom}` | 300 мс | `{"decision":"allow"}` / `{"decision":"modify","changes":{cpu_max_khz, governor}}` |
| launcher → модуль | `settings.changed`, `shutdown` | 1 с | `{}` |
| модуль → launcher | `ui.update` (`tile:<id>`, `row:<id>`, `widget:<id>`) | ≤ 4/с | — |
| модуль → launcher | `ui.notify`, `log`, `settings.set`, `config.get/set`, `game.launch`, `system.call` | — | `{}` |

### 7.2 Манифест `module.toml`

```toml
id = "thermal"
api_version = 3
name = "Температура и профили"
description = "Открывает настройки профиля процессора."
enabled = true
[run]
runtime = "bash"        # sh | bash | python3 | native
entry = "main.sh"
mode = "daemon"         # daemon | ondemand
[limits]
memory_mb = 16          # 8..64
[permissions]
net = false
read = ["roms"]
config_write = true

[[start.tiles]]
id = "temps"
title = "Температура"
icon = "thermometer"
open = "main"
```

### 7.3 Правила исполнения

В сборке 0.41 супервизор перечисляет до 16 модулей. Описание читается из
манифеста, пользовательский переключатель хранится отдельно на DATA. Отключённые
модули остаются видимыми. Штатные диагностические модули используют
`mode = "ondemand"`: их дочерние процессы запускаются только по X, возвращают
`result.message` и завершаются. При старте игры они пропускаются.

Формат импорта и границы реализованного API описаны в
[руководстве по модулям](MODULES.md). Исполнение происходит с правами штатной
службы. Следующие правила изоляции и инструменты относятся к целевой архитектуре.

- `modd` запускает модуль в cgroup v2 с `MemoryMax`, `TasksMax=16`, пустым env, uid из пула **61000–61999**, read-only rootfs; видны только свой каталог, `/data/modules/<id>` (rw), `/data/config/<id>.json` (ro), `/sys`, `/proc`.
- Права проверяются по манифесту; согласие пользователя один раз + sha256 digest, при расширении прав — повторно.
- Watchdog: 3 падения за 10 минут → модуль отключается до ручного включения.
- Привилегированные действия — только через файл-запрос `/run/svc/<id>.req` и root-хелпер (проверенный паттерн `thermal-apply.path`).
- DevKit: `modcheck <dir>`, `modrun <dir>`, пример-эталон `modules/examples/hello`.

## 8. Сейвы, стейты и «Продолжить с места»

### 8.1 Раскладка

```
/data/saves/<system>/<rom-id>/save.srm
/data/states/<system>/<rom-id>/slot0.state … slot4.state (+ .png 96×72)
/data/meta/games.sqlite        # rom-id, title, system, last_played, playtime, last_slot
/roms/.saves/                  # зеркало для людей (импорт/экспорт)
```

`rom-id` = sha1(размер + первые/последние 64 КБ файла) — устойчив к переименованию.

### 8.2 Атомарность

запись в `*.tmp` → `fsync` → `rename` → `fsync(dir)`; журнал `dirty` в `/data/meta`, при старте `saved` докатывает; проверка целостности zstd/sha при чтении; ротация 5 автослотов + 10 архивов экспорта (`tar.zst`).

### 8.3 Resume по A

| Ядро | Механизм |
|---|---|
| RetroArch | `--appendconfig` с `savestate_auto_load=true`, `savestate_slot=N` |
| PPSSPP | копирование нужного слота в `PPSSPP_STATE` + `--escape-exit` |
| Flycast / DuckStation / Mupen64Plus | собственные ключи слота/сейва |
| Порты | `RESUME_FILE`/конфиг порта; если нет — открывается обычный старт |

Если адаптера нет — кнопка A запускает игру без resume, кнопка SELECT — выбор слота.

## 10. Память: политика «без вылетов и фризов»

### 10.1 Бюджет

| Потребитель | Idle | В игре (класс F) |
|---|---|---|
| ядро + драйверы | 55–70 | 55–70 |
| svc + modd + saved | 8–12 | 8–12 |
| launcher | 13–17 | 0 (thin launch: выгружается) |
| dropbear/ssh | 3–6 (по требованию) | 0 |
| эмулятор | — | 120–180 (PSP), 70–90 (PS1) |
| **итого** | **≈ 80–105** | **≤ 250–270** |
| свободно | ≥ 620 | ≥ 420 (при 732 МБ) |

### 10.2 «presqueeze» перед запуском тяжёлой игры

1. `drop_caches` = `2` (не `3`: не трогаем dentry/inode).
2. Гасим необязательное: `smbd`, `simple-http-server`, `archr-panel`, `syncthing`, скрапер.
3. Thin launch: лаунчер выгружается (−30 МБ), возвращается по SELECT+START.
4. `vm.min_free_kbytes=16384`, `watermark_boost_factor=0`, `swappiness=60`, `MALLOC_ARENA_MAX=2`.
5. Профиль `heavy` (по требованию игры): zram 2048, `swappiness=100`, `lz4`.

Ожидаемый выигрыш: **+40–70 МБ** к `MemAvailable`, стабильность (нет OOM), а не FPS.

### 10.3 Контроль

- `/proc/pressure/memory`: `full avg10 > 5 %` → в UI бейдж «память под давлением» и авто-снижение настроек графики игры (по таблице классов).
- Профиль процессов: сторож `svc` убивает всё, что не в белом списке, при старте игры.
- zram: `lite` 1024 / `balanced` 1536 / `heavy` 2048; swap-файл на `DATA` — только по явному согласию (износ карты), по умолчанию выключен.

## 11. Производительность и термика

В 0.39 профили из меню задают лимит `scaling_max_freq` для `policy0`. Лимиты
eco, balanced и max — 816, 1008 и 1416 МГц соответственно. Выбирается наибольшая
частота из `scaling_available_frequencies` в пределах лимита. Настройка не
применяется, если выбранное значение ниже действующего `scaling_min_freq`.
Термоограничения ядра остаются активными. Профиль сохраняется в DATA и
восстанавливается при загрузке. Реальный лимит виден в **Сведениях**.

| Профиль 0.39 | Верхний предел CPU | Сценарий для измерений |
|---|---|---|
| `eco` | 816 МГц | меню и лёгкие игры |
| `balanced` | 1008 МГц | обычная нагрузка |
| `max` | 1416 МГц | тяжёлые ядра и порты |

Правила:
- Частоты менять только теми OPP, что есть в DTB: **408 / 816 / 1008 / 1416** (1296 не существует — ядро молча округлит вниз).
- Отдельный профиль частоты GPU, пороги 82/85 °C и журнал термодемона относятся к целевой политике. В 0.39 ограничение нагрева выполняет ядро.
- Цель термотеста под нагрузкой — ≤ 80 °C SoC.
- Целевые FPS (приёмка): 8/16-бит 60; PS1 50–60; N64 20–40; Dreamcast 25–50; PSP 2D 50–60, PSP-3D 20–30 (Capcom-класс); порты 30–60 по классу.
- В игре: никакой сети, сканирования, скрапинга, обновлений и записи логов выше WARN.

## 13. Этапы MVP

Обозначения: д — дни одного разработчика (агента), DoD — критерий сдачи.

| Этап | Что | д | DoD |
|---|---|---|---|
| **P0** | Boot bring-up: U-Boot, mainline 6.12, DTS-скелет, UART115200, busybox init | 5–7 | на экране UART видно ядро, панель инициализируется, есть shell по UART |
| **P1** | Панель + кнопки + стики + подсветка | 6–9 | T2 пройден: все 17 кнопок, A/B верно, картинка без артефактов |
| **P2** | Звук, питание, зарядка, LED, термозоны | 7–10 | T3 пройден: динамик/наушники, capacity/health, LED, трип-точки |
| **P3** | squashfs A/B, `/data`, `/roms`, ota, recovery | 4–6 | T5 пройден: обновление A→B и откат, `DATA` и `ROMS` не тронуты |
| **P4** | launcher: 6 разделов, обложки, настройки, бюджет памяти | 10–14 | T9 пройден: RSS ≤ 17 МБ, 0 кадров в покое, первый кадр ≤ 8.5 с |
| **P4b** | модульная система (`modd`) + перенос `thermal`/`saves` | 7–10 | модули стартуют, `ui.update`, файл-запрос root-хелпера, тест изоляции |
| **P4c** | `saved`: сейвы/стейты/атомарность/resume/импорт | 6–9 | T8+resume: A продолжает с места, kill -9 и power-cut не рвут сейв |
| **P5** | эмуляторы: RetroArch + ядра, PPSSPP, Flycast, DuckStation | 6–9 | T6 по классам A–G: 1 игра на систему, FPS ≥ целей §11 |
| **P6** | порты PortMaster, USB gadget NCM/MTP/host, Samba | 6–8 | T7: 10 портов запускаются, NCM-сеть и MTP работают |
| **P7** | полировка: профили, presqueeze, PSI, логи, CI, доки | 5–7 | K1/K2 подтверждены замерами, 30-мин соак без троттлинга |

**MVP = P0–P7 целиком, но в порядке приоритета:** P0→P1→P2→P3→P4→P5→P6→P4b→P4c→P7.

Ближайший этап после проверки 0.39 на V20 — **P6, PortMaster**. Упаковать
клиент и нужные рантаймы, подключить их к существующему разделу «Порты» и
проверить запуск, геймпад, звук, выход в меню и сохранения. Рантаймы портов
загружаются по запросу, в простое целевые лимиты K1 сохраняются.
Итого **62–89 д**; первая пригодная к играм сборка (без модулей) — к концу P5 (~38–49 д).

Что **не** входит: 1512 МГц, Wi-Fi-пайка, Bluetooth, netplay, скрапер «на лету», видеовыход.

## 15. Риски и решения

| Риск | Вер. | Влияние | Решение |
|---|---|---|---|
| DDR-init не заводится на mainline | сред. | блокер | взять готовый idbloader из Arch-R clone (проверен), fallback — стоковый BSP-загрузчик |
| DSI-панель не стартует | выс. | блокер | init-sequence из стокового DTB (`rf3536k3ka.dtb`), поэтапная отладка через UART |
| Звук на клоне молчит/тихий | сред. | ср. | клон-вариант audio (`simple-audio-card` вместо `rk817-codec` напрямую), fallback — усиление в микшере |
| A/B squashfs не влезает в 700 МБ | сред. | ср. | пересчёт состава: вынести тяжёлые ядра в `DATA`-пакет |
| PortMaster не находит `controlfolder` | выс. | низк. | путь `/roms/ports/PortMaster` как в Arch-R + совместимость флагов |
| Нет Wi-Fi | факт | низк. | документированная поддержка USB-донглов + Ethernet через OTG-хаб |
| PSP-3D не 30 FPS | выс. | низк. | честные цели §11, авто-настройки графики, presqueeze |
| 1512 МГц «дожать» | низк. | низк. | только эксперимент: патч `cpufreq/boost`, vdd 1.40 В, отдельный профиль, не в MVP |
| Износ microSD от swap | сред. | ср. | swap по умолчанию выключен, только по согласию |

## 16. Миграция с Arch-R/ArkOS (обратная совместимость)

### 16.1 Что переносится автоматически

1. `/roms/*` (вся библиотека) — без изменений.
2. `gamelist.xml` и `media/` — без изменений (превью идут в иконки).
3. `*.srm`, `*.state`, `*.battery`, `*.rtc` — мигратор `saved --import <old-root>`.
4. `retroarch.cfg`: импорт ключей по таблице §16.2, остальное — дефолты прошивки.
5. Порты `/roms/ports/**` — работают, `control.txt` по возможности родной.

### 16.2 Маппинг конфигов (фрагмент)

| Арх-Р `system.cfg` | Наш `/data/config/system.toml` |
|---|---|
| `system.language`, `system.timezone`, `system.kblayout` | `[locale] language/timezone/keyboard` |
| `system.cpugovernor`, `enable.turbo-mode` | `[power] governor/profile` |
| `display.brightness` | `[display] brightness` |
| `audio.device`, `audio.volume` | `[audio] device/volume` |
| `ssh.enabled`, `samba.enabled`, `simplehttp.enabled` | `[net] ssh/samba/http` |
| `usbgadget` conf | `[usb] mode` (ncm/mtp/host) |

### 16.3 Сохранение пути отката

Пользователь всегда может: (а) вернуться на Arch-R, записав его образ; (б) откатиться на `SYS_A/B`; (в) вынуть карту и прочитать `ROMS` на ПК (exFAT).

### 16.4 Порты: совместимость

`/roms/ports/<port>/` + `<Port>.sh` + `PortMaster/` с `controlfolder=/roms/ports/PortMaster`. В лаунчере порт — отдельная «система» `ports` с превью из `media/`.

### 16.5 Прошивальщик (Windows)

`scripts/flash.ps1`: проверка диска по размеру/модели, `Clear-Disk`, запись образа, **MBR последним** (иначе Windows монтирует FAT32 и получает `win32=5`), верификация SHA256, затем копирование оверлея панели при необходимости.

## 17. Правила работы агента

### 17.1 Первые шаги (по порядку)

1. `git clone <repo> && cd firmware && cat AGENTS.md`
2. Прочитать §1, §13, §17; завести ветку `feat/p0-boot`.
3. Собрать bootstrap-образ с загрузчиком из Arch-R clone, прошить, снять UART-лог.
4. Зафиксировать в `docs/journal.md`: что видно, какие ошибки, что дальше.
5. Дальше — по одному этапу, каждый со своим тестом и коммитом.

### 17.2 Обязанности на каждый коммит

- Тесты этапа зелёные, метрики записаны в `docs/metrics.md`.
- Обновлён `docs/journal.md` (1–5 строк: что сделано, что сломалось).
- Изменения в спецификации — отдельным коммитом `docs:`.
- Никаких «временных» костылей без `TODO(p0-…)` с номером этапа.

### 17.3 Диагностика на устройстве

```
cat /proc/meminfo; cat /proc/pressure/memory; zramctl; swapon --show
cat /sys/class/thermal/thermal_zone*/{type,temp}
cat /sys/devices/system/cpu/cpufreq/policy0/{scaling_cur_freq,scaling_available_frequencies,scaling_governor}
cat /sys/class/power_supply/battery/{status,capacity,voltage_now,current_now,charge_full,charge_full_design}
dmesg | grep -iE 'dsi|st7703|rk817|dwc2|mmc|panfrost'
journalctl -b -o short-precise | tail -n 200
```

### 17.4 Запреты

1. Не писать в BootROM/DDR-init; не менять `idbloader` без согласования.
2. Не трогать пользовательские разделы (`DATA`, `ROMS`) без бэкапа и подтверждения.
3. Не тянуть пакеты «на всякий случай»: каждый МБ RSS и секунда загрузки — под отчёт.
4. Не блокировать старт игры ожиданием сети/сканирования.
5. Не обещать FPS и «оптимизацию», которых нет в замерах.

## 19. Спорные моменты: что проверено и как решено

При вычитке v0.1 против реальных замеров, документации ядра и 4PDA найдены противоречия. Итоговые решения:

| # | Спорное | Было в v0.1 | Решено здесь | Почему |
|---|---|---|---|---|
| 1 | Бюджет ОЗУ | 65–95 МБ на всю систему | **≤ 150 МБ**, ожидание 80–105 | 65–95 достижимо только без драйверов GPU/DSI и без пользовательского слоя; 150 — честный предел из раскладки §10.1 |
| 2 | Время загрузки | ≤ 15 с | **≤ 12 с** до первого кадра | на Arch-R 20–30 с при systemd; наш busybox-init и прямой KMS дают запас, но 8 с — фантазия без измерений |
| 3 | Композитор | «без композитора» | **weston только transient для портов**, которые его требуют | часть портов PortMaster (weston_pkg) без Wayland не стартует; держать его резидентно = +30–40 МБ |
| 4 | Память лаунчера | 18–21/24–27 МБ | **13–17 МБ** (пик 18) | пересчитано по бюджету §6.4 с кэшем обложек 0.45 МБ |
| 5 | Сейвы | «на разделе с ROM» | **`/data` (ext4)**, зеркало `/roms/.saves` | swap и атомарная запись на exFAT невозможны; ROM-раздел остаётся «глупым» хранилищем |
| 6 | 1512 МГц | «дожать до 1512» | **вне MVP**, эксперимент | нужен `cpufreq/boost` + vdd 1.40 В; сейчас узел отсутствует, а `vdd_arm` max 1.35 В — обещание без патча ядра |
| 7 | Частота 1296 | фигурировала в профилях | **убрана** | такого OPP нет: 408/816/1008/1416; ядро молча округляет вниз и профиль врёт |
| 8 | NDS | «DraStic» | **melonDS** по умолчанию | DraStic — проприетарный, в свободную сборку не входит; совместимость DraStic-сейвов — через импорт `.dsv` |
| 9 | «Все 175 систем играбельны» | подразумевалось | **реестр полный, играбельность по классам** §9.1 | Saturn/DOS/Jaguar запускаются, но FPS не гарантируется — обещать нельзя |
| 10 | Супервизор модулей | `systemd-run` (как в Arch-R) | **свой `modd`**, протокол совместим с api 3 | systemd не берём (ADR-001), но протокол сохраняем — модули переносятся |
| 11 | Размер `SYS_A/B` | 700 МБ «по расчёту» | **измерить на P3**, при переполнении — вынести ядра в `DATA`-пакет | squashfs с 416 ядрами может не влезть; решение принимается по факту, а не на глаз |
| 12 | zram по умолчанию | 1536 | **1024 `lite`**, 1536 `balanced`, 2048 `heavy` | на 1 ГБ RAM большой zram в простое только мешает; профиль выбирается под игру |

Дополнительно уточнено по 4PDA и документации:

- **OTG на семействе ArkOS** не работает без скрипта `dr_mode` (пост #144886162) — у нас USB-режимы обязательный тест T7, а не «приятное дополнение».
- **ROCKNIX для клонов** ставится только версией `-b` + патч DTB (`rocknix.gosk.in/dtbo/`), у части клонов пропадает звук; **Aurknix** — форк ROCKNIX под клоны, рекомендуется DTB-тулзой как «Recommended».
- **dArkOSEN** (djparentx, релиз 11112026) — самая свежая из Debian-семейства, но официально заявлена под оригиналы; на клонах возможны сюрпризы по панели/звуку.
- **RAM-апгрейд**: чип `Nanya NT6CL256M32-H1`, попытки пайки на 2 ГБ на 4PDA успехом не закончились — в проекте не планируется (поэтому вся политика памяти строится на 1 ГБ).
- **Маркетинговые цифры** из шапки («RK3326 1.5 ГГц, Mali 520 МГц») не используются: только sysfs.

## 20. Дефиниция готовности MVP (Definition of Done)

MVP считается готовым, когда на одном устройстве одновременно выполнено:

1. `T1–T12` зелёные, логи и скриншоты приложены к `docs/metrics.md`.
2. Idle: **≤ 150 МБ** занято, **≥ 560 МБ** доступно, **≤ 6** демонов, 0 кадров в покое.
3. Загрузка: **≤ 12 с** до первого кадра, 20/20 успешных power-cycle.
4. Игра: PSP-3D (Lumines/Patapon-класс) 30 мин без `oom-kill`, без фризов > 250 мс чаще 1 раза в 10 минут, SoC ≤ 80 °C.
5. Библиотека: 175 систем в реестре, ≥ 60 систем проверены по 1 игре, 10 портов запускаются.
6. Совместимость: ROM и сейвы, скопированные с Arch-R, видны и играются; `gamelist.xml` читается.
7. Обновление A/B: успешное обновление и успешный откат после искусственного сбоя.
8. Документация: `README.md` (сборка/прошивка), `AGENTS.md`, `docs/journal.md`, эта спецификация в актуальной версии.

## 21. Брендинг: DEEPoS

**Имя системы:** `DEEPoS` · слоган: `OPEN HANDHELD SYSTEM` · версия на сплэше: `v0.1`

### 21.1 Загрузочная картинка

| Что | Файл | Параметры |
|---|---|---|
| Сплэш U-Boot / ядра | `branding/deepos-boot.bmp` | **640×480, 24-bit BMP** (U-Boot Rockchip ждёт 24 bpp; если сборка просит 16 бит — конвертировать: `ffmpeg -i deepos-logo.png -pix_fmt rgb565le deepos-boot16.bmp`) |
| Превью / доки | `branding/deepos-logo.png` | тот же кадр, PNG |
| Иконка лаунчера | `branding/deepos-icon-128.png`, `deepos-icon-64.png` | RGBA, плитка `D` со свечением |
| Генератор | `branding/make-logo.py` | Pillow+numpy, детерминированно, легко перегенерировать |

### 21.2 Визуальные правила (совпадают с UI §6.2)

```
фон сплэша      #05070C
градиент слова  #1458EB → #96E2FF
свечение        #1E6BFF  (глоу ~14 px, alpha 32 %)
линия/пунктир   #2660BE
подпись         #6CA8F0
```

- Логотип — только типографика: `DEEPoS` + тонкая линия + подпись. Никаких месяцев, шестерёнок и 3D.
- Время показа: **≤ 0.8 с** до первого кадра лаунчера и столько же при выключении (плавно на чёрный, без анимаций).
- Показывать картинку могут три места: `bootlogo` в U-Boot, `logo_kernel.bmp` в ядре, собственный сплэш `svc` перед стартом лаунчера. Достаточно **одного** (U-Boot) + чёрный фон ядра: экономит 1.2 МБ на `BOOT`.
- При старте игры сплэш не показывается (K1 — не тратить время и кадры).

### 21.3 Инструкция интеграции

1. Положить `deepos-boot.bmp` в `BOOT/` как `logo.bmp` (или путь из `boot.cmd` сборки).
2. В `extlinux.conf`/`boot.scr` оставить `quiet` и не включать `splash` Plymouth-подобные пакеты (их в сборке нет — намеренно).
3. В лаунчере: экран «Продолжить» рисуется сразу; сплэш `svc` — только на медленной загрузке (> 1.5 с после монтирования `/data`).
4. Проверка: `T1` — 20 power-cycle, сплэш не мерцает, нет чёрного экрана подольше 1 с.
